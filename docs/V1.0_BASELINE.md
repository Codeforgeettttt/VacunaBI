# V1.0 — Línea base técnica de VacunaBI

**Fecha de preparación:** 2026-11-16  
**Origen del código:** base original aportada por el equipo en el ZIP `Proyecto_vacunacion-main.zip`.

## Propósito

Preservar la aplicación existente de cobertura de vacunación como punto de partida para los incrementos V1.1 a V2.0. El repositorio contiene exclusivamente código de producto, pruebas, dependencias y documentación técnica útil para desarrollar y ejecutar VacunaBI.

## Componentes de la V1.0

| Archivo | Propósito |
| --- | --- |
| `etl.py` | Consulta de la API CKAN, limpieza, agregación, KPIs y generación de archivos. |
| `dashboard_template.html` | Estructura HTML, CSS y JavaScript del dashboard. |
| `chart.umd.min.js` | Librería Chart.js distribuida localmente. |
| `app.py` | Aplicación de escritorio mediante pywebview. |
| `requirements.txt` | Dependencias de procesamiento. |
| `test_etl.py` | Pruebas originales de limpieza. |
| `test_etl_regression.py` | Pruebas de regresión de cálculos y anomalías. |
| `.github/workflows/actualizar.yml` | Pruebas, ETL y publicación web opcional. |

El generador de un documento académico que existía en el repositorio fuente **no forma parte de VacunaBI**. Se retiró de este repositorio sin modificar los componentes de la aplicación.

## Flujo de ejecución

```bash
python -m pip install -r requirements.txt
python test_etl.py
python -m unittest -v test_etl_regression test_dashboard_template
python etl.py
```

El ETL genera en `salidas/` las fuentes descargadas, datos transformados, indicadores y `dashboard.html`. Esta carpeta está excluida de Git.

Para abrir la aplicación de escritorio:

```bash
python -m pip install pywebview==5.3.2
python app.py
```

## Validaciones de referencia

- El `test_etl.py` original dio `OK` en una revisión local del ZIP fuente.
- La ejecución automatizada de GitHub Actions de 2026-11-16 ejecutó el ETL, las pruebas de regresión y las pruebas estructurales de la V1.1.
- La validación visual en navegador y pywebview continúa pendiente para cerrar V1.1.
- La publicación GitHub Pages es opcional y requiere habilitarla en Settings.

## Limitaciones metodológicas

- Los recursos integrados en el código se refieren a Bogotá D.C.; aún no existe un procesamiento validado de Cundinamarca.
- Las comparaciones deben corresponder al mismo biológico, periodo y denominador.
- Valores mayores al 100 % deben conservarse y analizarse.
- La comparación entre etapas del esquema no es un seguimiento individual de una cohorte.
- Los años en curso requieren identificación de datos parciales.

## Reglas de continuidad

1. No modificar indicadores en una tarea exclusivamente visual sin justificarlo.
2. Conservar pruebas que protejan los cálculos de cobertura y la calidad.
3. Documentar cada versión según sus requisitos y criterios de aceptación.
4. Mantener exclusivamente recursos de la aplicación y documentación técnica de desarrollo.
5. Mantener commits descriptivos y atribuir contribuciones según el trabajo realizado.
